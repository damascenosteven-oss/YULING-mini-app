# 为结构化大纲提供准确修复反馈与标准生成模式

## Critic Loop

问题：union 错误按最少错误数选择分支，会给已知类型页面提供错误类型的修复建议。隔离调用还显示：首次模型花费约 39.2 秒返回 schema 不合规的 JSON，下一次修复触发 45 秒时限。首轮 6946 个输出 token 中 5171 个为思考 token。这些证据不能证明历史 502 原因，也不能预先保证关闭思考就能成功。

维持现状 35/100：无变更成本，但保留已复现的错误反馈。只增加超时 60/100：增加等待与潜在费用，无法纠正误导反馈。根据草稿选择类型/版式反馈、修复时提供草稿并显式采用标准模式 92/100，采用：增加修复请求输入用量，需要维护脱敏回归；换取可解释的反馈和明确的请求参数。

## 决定及边界

仅对官方 api.deepseek.com、deepseek-flash 的结构化大纲请求发送 thinking disabled，不扩展到未知模型或自定义接口。既有 45/90 秒、输出 token 上限、两次尝试和单次证据获取不变。第二次请求携带当前请求的规范化失败草稿，标记为不可信数据；不记录正文。

保持 DeckOutline 结构、renderer、技能及引用契约不变。未知 discriminator 必须由模型依据允许值修复，不能用猜测映射掩盖。验收是正确反馈、完整校验和可复现调用链；模拟入口不代表真实云端质量、性能或业务恢复。此次不部署，也不改博查配置、资源预算和引擎/视觉基线。
