# 固定运行环境归档的校验缓存

## Critic Loop

问题：发布 #6 命中两个源码缓存后，构建器仍重新下载 Node、Chrome 和 pnpm，并在 TLS EOF 处失败；接力随单次请求退出。构建输出每次位于新临时目录，当前代码证实这些下载不能跨请求复用。网络路径偶发故障是已验证的现象，具体链路根因未确定。

保持逐次下载 30/100：无新增状态，但每次发布仍依赖三个下载端点。只调整代理 55/100：改动小，但本机直接与代理路径均观察到间歇性失败。仓库外的校验缓存与有界预热 90/100，接受：发布不再等待运行环境下载，代价是约 230 MiB 本机状态、每次哈希检查和并发保护。

## 决定与边界

缓存以现有锁文件的 URL、文件名和 SHA-256 为唯一来源；完整下载与哈希通过后才原子发布。预热最多三次，每次十分钟总时限和 120 秒无进展时限，间隔 2 秒与 5 秒。发布离线读取缓存，损坏、缺失和符号链接一律失败；构建输出仍为单请求隔离目录。

接力将一个请求的失败记录到 GitHub 并继续轮询，重复请求保持幂等拒绝；上传与激活不自动重试。配置、身份、正式引擎锁、视觉阈值、Golden 图片和服务器资源不变。CI 不使用电脑缓存，继续验证标准构建路径。
