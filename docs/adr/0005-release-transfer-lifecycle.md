# ADR 0005：受限传输的阶段预算、产物身份与接收器升级

## Critic Loop

问题：约 888MiB 的发布包在真实 upload 请求中触发共享 900 秒截止，缺少阶段耗时；
只重跑 release 时 run_attempt 改变，按名称推算会与成功 build 的产物脱节。
证据：GitHub run 40439733024/job 121982025995 日志，以及 ssh-client.py、release.py、test-site.yml。
不能从这条错误断定网络或内存是根因。

| 方案 | 成本与副作用 | 评分 |
| --- | --- | --- |
| 维持现状 | 无新维护，但无法诊断和可靠重跑 | 40 |
| 仅延长总时限 | 改动小，仍无法区分传输/校验，死连接占锁 | 65 |
| 分阶段、固定产物 ID、显式接收器升级 | 增加协议日志和升级测试，保留现有信任边界 | 90，采用 |

所有者于 2026-10-27 批准第三项。预算：传输 45 分钟、无数据 120 秒、整理 15 分钟，
客户端 upload 65 分钟，release job 90 分钟；deploy/rollback 保留 15 分钟。
stderr 为受限字段的逐行事件；stdout 保留单一最终响应。客户端只显示经过验证的事件，
不回显原始 SSH 消息，必须同步消费输出并保留退出码。旧服务能力不符时先拒绝传包。
所有源版本、归档、镜像、资源、端口与锁检查保留；不信任请求传入的超时或程序路径。

build 的 artifact ID 是 release 唯一取包依据。重跑沿用成功 build 的输出，缺失或过期拒绝。
升级是独立管理员操作，不授予部署账号升级自身的能力；校验旧哈希、持相同操作锁，
备份旧文件、原子替换并验证，失败恢复旧文件。既有 app.env、SSH 和 Caddy 配置不变。

## 验收和推广

红绿和隔离 SSH 测试覆盖边界，完整工程 CI/最终镜像验证后交付 PR。
用户合并后代理核验并升级接收器，新的发布由用户手动触发；实际网络耗时和业务容量另验。
本决策不授权扩大资源、关闭门禁、自动重试发布或变化正式视觉验收标准。
