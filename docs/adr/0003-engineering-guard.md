# ADR 0003：复用共享检查器，独立接入工程门禁

所有者于 2026-10-26 批准本仓库接入本地 Git 钩子和 PR CI，独立交付，合并后
再恢复部署 Issue #8。检查器保持现有版本，不另写第二套规则。

## Critic Loop

问题：新仓库缺少登记与自动检查，部署交付需要可重复核验批准状态和源码。
证据：我跑过登记查询、钩子盘点和 GitHub 查询；仓库未登记，没有自定义钩子，
main 未保护。直接运行检查返回未登记，不等于发生 Git 写入拦截。

| 选择 | 成本与副作用 | 评分与决定 |
| --- | --- | --- |
| 共享检查器接入本地与 CI | 增加策略维护和一次 PR；共同 Git 目录的其他分支也受约束 | 92，接受 |
| 本次人工等效核验 | 交付较快，但自动保护缺口持续 | 72，用户未选择 |
| 保持现状并等待 | 无治理改动，但部署交付停滞 | 40，不采用 |

策略只登记 Issue #9，冻结时间不变，不添加 Dependabot 豁免。独立 PR 便于先
审核规则，再审核部署。GitHub 分支保护及合并由所有者操作。既有 Codex 适配器
不变；安装声明必须有真实入口验证。门禁不代替代码审查或真实服务器验收，
也不保证防御恶意本地文件拥有者。
