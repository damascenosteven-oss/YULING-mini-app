# ADR 0004：在 GitHub 构建、手机手动发布测试镜像

## 决策与授权

2026-10-26 用户明确批准本方案。采用 GitHub 构建 Linux 镜像及受限 SSH 成品交付，
服务器仅运行镜像；所有者手动触发发布/回滚，不在合并时自动发布。
这改变部署边界，故需要 ADR；不改变 PPT 模型、视觉基线或正式引擎锁。

## Critic Loop

问题：现有 CI 只检查代码，缺少手机发布入口。共享服务器内存有限，
直接编译 Next/安装浏览器会与现有业务竞争资源；容器里的 Caddy 不能用
127.0.0.1 连接宿主服务。

证据：已读取 ci.yml、自定义 src/server.ts、生产部署示例与 Cookie 路由；
用户回传 Docker 可用、约 829MiB 可用内存、已有 Caddy 单文件只读挂载。
真实服务器能力尚未测量，候选与正式引擎锁的区别已明确告知并获准。

| 选项 | 成本与副作用 | 评分/结论 |
| --- | --- | --- |
| 保持现状 | 不改变系统，但手机不能发布 | 40，拒绝 |
| GitHub 构建固定镜像 | 新增打包与受限发布入口；依赖/字体可追溯，可限制内存 | 88，接受 |
| 压缩包与主机运行环境 | 接近旧示例，但主机 Chrome/Python/字体漂移和维护更多 | 74，未采用 |
| 共享服务器直接构建 | 初期脚本少，编译峰值会竞争现有业务资源 | 30，拒绝 |

以上评分为设计判断，不是性能测试结果。初始 512MiB 实测失败后已暂停并报告；
后续资源决定见下节，不放宽视觉门禁、不自动扩容。

## 已接受的容量试跑修订

问题：初始预算无法完成真实 Python/Chrome 检查。
我跑过：512MiB 出现 OOM，768MiB 在同时运行网页服务时超时；
1GiB 本机诊断通过但计费峰值触顶。峰值含可回收文件缓存，
不能把触顶解释成已证明无法运行，也不能把一次通过解释成持续容量通过。

| 选项 | 成本与副作用 | 评分/结论 |
| --- | --- | --- |
| 保持 512MiB 并暂停 | 无新增资源竞争，但已失败，无法继续试跑 | 45，未采用 |
| 同规格、1 核/1GiB、单任务受控试跑 | 可能与现有网站竞争内存；必须观察真实负载并允许中断恢复 | 82，所有者接受 |
| 扩大服务器规格 | 更大余量但增加费用，所有者选择保持规格 | 70，未采用 |

所有者回复“可以”后，采用第二项。memory 与 memory-swap 同为 1024MiB，
不增加容器交换空间。保留 768MiB 可用内存/8GiB 磁盘最低检查，
它们是进入试跑的必要条件，不是容量批准。Chrome 可写 HOME/XDG 目录属于
非 root 镜像运行修复，不改变浏览器渲染参数、基线或引擎输出。
真实服务器发布及容量验收仍由所有者操作；本机通过不替代该验收。

## 约束

- 引擎候选仅通过镜像发布清单显式配对，不修改 ENGINE_BASELINE.json。
- 独立 Docker 网络，端口绑定已验证的现有 Caddy 网络宿主网关；禁止全网卡绑定，
  由外部连接测试验证无法直接访问。Caddy 只追加新主机名并安全热加载。
- 受限 SSH 使用固定命令、可信服务器公钥和服务器预装的 root 所有发布程序；
  不接受任意路径、shell、Docker 选项或非本应用资源操作。
- 归档先校验后导入；应用运行非 root、固定资源上限，业务秘密不参与构建。
- 生产 Cookie 必须 Secure；可信边缘转发实际客户端地址，不能让外部伪造限流身份。
- 失败自动恢复上一个已检查版本；首次失败恢复新增站点配置，其他项目保持原状。
- 不安装自托管 GitHub runner；不授予 PR 代码服务器部署凭据。

## 验证与交付

测试真实应用入口、实际发布程序、错误传播和恢复，额外证明故意错误被拒；
最终镜像验证 12 页几何与独立重复捕获。真实外部 API、容量、手机体验由所有者
在服务器最终验收。当前无正式 Mac 批准；不冒充完整硬闸已安装。

## 2026-10-27 恢复交付

所有者批准从已合并门禁的最新 main 恢复 Issue #8。编号由 0003 顺延为 0004，
原部署与 1GiB 试跑决定保持；共享检查器不变，新增本 Issue 批准记录并重跑验证。
