# 锁定依赖预取与离线镜像安装

## Critic Loop

问题：手机发布 #9 的源码和运行环境缓存已命中，但 Docker 中的冻结 pnpm 安装仍在线下载锁定包，遇到 `ECONNRESET` 后构建失败。现有代码与日志验证这一缺口；具体网络故障来源未确定。

维持在线安装 30/100：无新增状态，但重复发布继续依赖即时下载。只增加在线重试 60/100：改动小，却不能消除发布请求对包仓库的依赖。仓库外完整性校验预热加镜像内离线安装 90/100，接受：增加电脑缓存、预热步骤和维护成本，换取发布构建不在安装阶段临时拉取依赖。

## 决定

缓存由 `package.json`、`pnpm-lock.yaml`、固定运行环境锁和 Linux 架构共同标识；只接受固定 Node/pnpm 的完整预取、pnpm store 检查与独立冻结离线安装。发布只读缓存，缺包、损坏或身份不符即停止，不换版本、不在线回退。CI 临时预取后走相同离线构建。审计和其他既有联网检查继续失败阻断；本决策不宣称整个镜像构建完全离线。

用户保留手机触发、合并和业务验收。服务器、正式引擎锁、Golden、产品接口及 Mac 正式验收不在本决策范围。
