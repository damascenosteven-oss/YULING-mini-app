# 手机发布接力的提交校验源码缓存

所有者于 2026-10-28 明确批准本计划。授权 Issue 分支的代码、测试、推送和 PR；合并、手机发布和业务验收仍由所有者操作。

## 问题与选择

我跑过：手机发布 #4 在固定引擎下载、#5 在应用提交获取时分别遭遇 Git TLS 中断，均未进入服务器上传。同一应用 SHA `0de7cd3edd590a63f03fc16c5c8b2ea2a0d3cf2b` 与引擎 SHA `be73ccd4e811bd877fb2635fd7dfc3ca3ad8e192` 的本机生产镜像构建及两次独立 12 页捕获通过。GitHub 仓库报告的应用和引擎大小约 20 MiB 和 16 MiB。

所有者选择仓库外的提交校验缓存，并允许仅源码获取最多三次有限重试。保持现状 30/100；每次完整下载并有限重试 68/100；缓存固定提交并有限重试 88/100，采用。缓存增加本机状态，但减少重复的 GitHub 连接。细节与副作用见 ADR 0008。

## 交付行为

- 接力先照常经 GitHub API 核对请求身份、受保护的当前 `main`、完整 SHA、Checks、有效期和重复状态；API 不可达时即使缓存命中也停止。
- 在现有 `state_dir` 下保存应用和引擎两个固定来源的 Git 缓存。首次或缺少目标提交时，获取完整对象；最多尝试三次，每次限时 90 秒，间隔 2 秒和 5 秒。缓存来源不符、对象损坏或获取失败时停止，绝不改用旧提交。
- 从应用缓存建立临时干净检出，核对 HEAD 等于请求 SHA；把已验证的固定引擎缓存通过构建器现有 `--engine` 参数传入。镜像验证、两次 12 页捕获、请求再检查、受限上传、激活和回滚保持原行为。上传、激活或整个请求不自动重试。
- 提供仅准备源码缓存的电脑入口；不生成发布请求、不构建镜像、不连接服务器。缓存及其诊断只在仓库外，不含令牌、密钥或客户内容。

## 验证与交付

先以故意错误证明新断言会拒绝，再实现并恢复通过。覆盖首次填充、命中、新提交、两次失败后成功、三次失败、90 秒超时、损坏、错误来源、旧版替代拒绝，以及失败绝不上传或激活。至少一条测试走请求核验→缓存检出→镜像验证→受限 SSH 调用→GitHub 状态的真实形状。

执行工程门禁、冻结安装、`pnpm validate`、portable、跨仓库测试、12 页 geometry、生产构建、依赖审计、秘密扫描，并在本机用当前完整 SHA 做不上传服务器的生产镜像及两次独立 12 页零差异验证。记录命令、退出码、版本和跳过项。推送 Issue #18 分支，PR 正文包含 `Closes #18`，核对当前提交的 `engineering-guard`、`app-checks`、`release-checks`。所有者合并后，先在电脑预热缓存并确认接力等待，再由所有者手机触发新运行。
