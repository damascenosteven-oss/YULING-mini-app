# 修复大纲生成格式与自动修复流程

所有者于 2026-10-30 明确要求实施完整计划，授权独立 Issue 工作树内的代码、测试、分支推送与审核 PR；不授权合并、部署、服务器操作或付费生成。

## 依据和选择

我跑过：隔离的 10 页联网大纲请求完成三次搜索，首次模型输出未通过页面结构校验，第二次请求触发既有 45 秒时限并返回 504；不能据此认定历史 502 的完整原因。纯样本证明：现有 formatter 仅按错误数量选择 union 分支，会把 items 内容错误的 bullets 页误报为 cover。

所有者明确选择标准模式。仅官方 api.deepseek.com 的 deepseek-flash 大纲请求显式关闭 thinking，其他模型与自定义接口保持现状。关闭思考的实际效果待真实服务验收，不能以模拟测试替代。

## 已批准修改

- 保留模型、token 上限、45/90 秒时限、最多两次模型尝试及单次搜索证据获取。补充正确的要点页和带引用表格示例。
- 使用规范化草稿的 type/variant 选择相关校验错误；未知类型或版式列出允许值，不猜测转换，不降低 schema、页数、技能、引用校验。
- 第二次请求携带上一轮草稿及准确约束，草稿仅在当前请求内存中使用，不入日志或持久化；修复后完整复验。
- 公共响应、错误码和 HTTP 状态不变。记录同一 requestId 下的尝试、分类、耗时、可用上游状态、结束原因和数字用量；不记录密钥、Cookie、提示词、草稿或模型正文。
- 不新增依赖、用户设置、页面类型或产品数据结构。ADR 的取舍与副作用见 0012。
