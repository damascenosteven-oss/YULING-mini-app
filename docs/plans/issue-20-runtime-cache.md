# 手机发布运行环境缓存与接力故障隔离

所有者于 2026-10-28 明确批准本计划，并亲自建立 Issue #20。授权 Issue 工作树中的代码、测试、分支推送和审核 PR；合并、手机触发发布与业务验收由所有者操作。

## 目标与证据

我跑过：手机发布 #6 的应用及引擎源码缓存命中，但在 `pinned_image_build` 阶段下载锁定的运行环境文件时发生 TLS EOF；未执行受限上传或服务器激活。构建器每次使用新临时输出目录下载三个文件；请求失败后 `StepFailure` 未被接力循环捕获，进程退出。见 ADR 0009 的方案比较。

## 实施

- 在仓库外的接力 `state_dir/runtime-cache` 缓存 `runtime-lock.json` 指定的 Node、Chrome、pnpm 归档。固定文件按名称和 SHA-256 区分；拒绝符号链接、损坏或部分文件；写入使用临时文件、校验和原子替换。每次使用时重新校验，复制到独立构建输出后再次校验。
- 扩展电脑预热入口：缺失文件最多下载三次，每次总时限十分钟，连续 120 秒无进展失败，间隔 2 秒和 5 秒。发布只接受完整校验缓存；缺失或损坏时失败，不现场下载、不换版本。
- GitHub API、`main`、完整 SHA、Checks、有效期与重复请求照常核验。单次请求失败后将对应 Deployment 标为失败，接力继续等待新请求；不自动重试旧请求、上传或服务器切换。配置与凭据错误继续显式失败。

## 验证与交付

先证明故意损坏缓存和失败构建会被拒绝，再覆盖预热、命中、缺失、截断、超时、并发及失败后继续处理下一请求。真实入口测试证明失败不上传、不激活。运行工程门禁、部署回归、冻结安装、`pnpm validate`、portable、跨仓库测试、12 页 geometry、生产构建、依赖审计、秘密扫描及镜像重复捕获，记录实际命令、版本、退出码与跳过项。PR 正文关联 `Closes #20`，核对三个 CI 检查。

合并后只在电脑端核对并预热运行环境缓存，完成不上传服务器的镜像与两次 12 页零差异检查，启动接力并确认等待。下一次 `main → publish` 仍由所有者手机手动触发；本 Issue 不修改服务器、产品接口、Golden 图片或正式引擎锁，也不声称 Mac 验收。
