# 手机触发、电脑构建并直传测试站

所有者于 2026-10-27 明确要求实施本计划。授权诊断、代码和本机接力程序准备、测试、Issue 分支推送及 PR；手机正式发布、合并和应用验收仍由所有者操作。
我跑过：GitHub 云端 SSH 4MiB 约 267 秒，电脑向同一服务器经 SSH 传真实镜像包前 128MiB 约 19 秒。完整包直传尚待验证，不能宣称发布已经成功。COS 上传返回 HTTP 错误，不采用中转。

## 已批准选择

优先私有发布仓库及专用 Runner，但仅限可验证私库分支保护的账号。认证 GitHub API 未返回账号套餐，电脑操作工具无法可靠确认浏览器 URL 而停止；不能证实私库强制保护。因此按所有者选定的备选路线，复用现有公开仓库及其保护，使用电脑接力程序。保持手机在本仓库 Actions 手动点 publish/rollback。

## 交付行为

- 手动工作流只接受受保护 main 与固定选项，记录完整应用 SHA、运行编号、尝试编号、操作和有效期；不再构建或传输大型 GitHub 产物。
- GitHub Deployment 状态作为小型请求与结果通道。电脑接力程序仅接受本仓库所有者发起、未处理且未过期、仍为 main 当前提交的请求；再次独立核对来源和所需检查。
- 电脑已登录、Docker Desktop 正在运行。接力程序使用专用、最小权限的 GitHub 凭据，凭据仅在本机安全存储；部署私钥仅在本机受限存储，不进入仓库、构建上下文、聊天或日志。
- 电脑按原固定工具链、固定引擎锁构建和验证最终镜像，保留两次独立 12 页零差异候选检查；通过原受限 SSH 接收程序上传校验并发布，回滚调用原受限操作。
- 同一服务器串行；离线、过期、重复、取消、版本变化、检查失败、坏摘要、上传失败时明确报告并停止，不自动重试、切换或扩容。GitHub 工作流等待电脑结果并在手机 Actions 显示真正成功或失败。
- 旧云端大包路径在新的真实入口测试通过后退役；不改产品 API、数据、Golden、正式引擎锁、Caddy 或服务器资源预算。

## 验证与交付

按红绿测试覆盖绑定 SHA、身份、过期和重复、离线和取消、摘要、上传失败及回滚；至少一条真实形状的工作流请求→接力程序→受限 SSH→GitHub 状态路径。完整包先做不切换版本的传输及 SHA 校验。运行工程门禁、冻结安装、validate、portable、跨仓库、geometry、生产构建、审计、秘密扫描及镜像重复性验证，记录实际命令、退出码和哈希。
PR 正文 Closes #16，报告当前提交三项 CI；由所有者审核合并并首次手机触发正式发布。仅完成真实网站及普通 PPT 业务验收后才能称上传问题解决。

保持云端直传 25/100；COS 中转 30/100；可保护私库 Runner 88/100；现有公开仓库电脑接力 82/100，采用备选。详见 ADR 0007。
