# Issue 48：不可见全局资源回收

## 故障与边界

所有者报告：iPhone 14 Pro Max、iOS 26，在原分享作品末页出现整页白屏和 Safari“重复出现问题”；未取得设备进程终止记录。服务器健康正常、无 OOM。这不能确认手机 WebContent/GPU 进程被终止的具体原因。

我跑过：此前仅检查隐藏 `.slide`，遗漏播放器外的透明背景及结束扫光。对同一冻结画面释放这些不可见资源后，Chromium 合成图层 27 → 19、绘制图层面积 30,846,984 → 15,374,248，三份 PNG 字节完全相同。面积不是实际 GPU 内存，桌面结果不是 iPhone 验收。

本次保留可见粒子、模糊、3D、转场时长、文字动画及地图缩略图；只在原内容已经完全不可见时释放背景或扫光，再次进入前恢复。COS 原作品不变；原始、已知 v1/v2 和 v3 通过严格签名还原后统一适配，重复适配不累加。

## 已运行的回归与测量修正

- 旧实现首次红测：`fully transparent background must exit drawing`，退出 1。修复后相同真实 Python 生成、sandbox iframe、三倍像素密度入口通过。
- 故意恢复隐藏背景、结束扫光或归零相位，断言均拒绝；对过期回收和后台时钟的故意错误另有真实浏览器断言。
- 旧版 WebKit 三倍像素密度测试曾在固定 100ms 后没有取得下一帧，数字未前进。独立记录实际 RAF 时间后，改为读取真实恢复帧，并将后台暂停延长至 2000ms（超过原 1600ms 动画）；仍要求继续前进且不能跳到终点，故意取消暂停补偿必须失败。
- 早期背景相位测试分两次浏览器调用测量切页两端，WebKit 在两次调用之间继续播放了数百毫秒，造成假偏差。改成同一浏览器任务内取前后读数后，两种时钟的短对照都通过；但百次翻页后的完整高密度路径仍发现墙钟与实际 CSS 进度有约 135ms 的差距。因此最终用仍可见的原生 CSS 动画进度计算隐藏期间相位，并在恢复动画的原生首帧就绪后对齐；快速切页使旧回调失效。持久状态只存目标和数字，不保留隐藏动画句柄；失败日志仍保留。
- 初次部署单测缺少 root 的 Node PATH，141 项通过、1 项环境错误；显式使用固定 Node 后 142 项通过。工具链不做全局修改。
- 首轮完整跨仓库 100 项通过；增加更严格故意错误后曾有 1 项因缺少动画的诊断不明确而失败。补明确断言后须以最终源码的完整复测为准。
